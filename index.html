  • Không thể vô hiệu hóa tức thời: JWT là hoàn toàn Stateless, Server không giữ session. Khi bị lộ token, Server không có cách nào ngăn kẻ gian gửi request.
  • Cửa sổ tấn công (Attack Window) quá rộng: Bất kỳ ai sở hữu token (qua XSS/Sniffing) đều có toàn quyền thực thi suốt 30 ngày.
  • Claims không cập nhật: Khi tài khoản bị đổi Role hoặc khóa tài khoản, Token cũ vẫn mang quyền lực cũ cho đến khi hết hạn.

Thiết kế Database & Endpoint Cấp Lại Token

1. Entity RefreshToken (MySQL / JPA)

@Entity
@Table(name = "refresh_tokens")
public class RefreshToken {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true)
    private String token; // UUID ngẫu nhiên

    @Column(nullable = false)
    private Instant expiryDate;

    private boolean revoked = false; // Cờ thu hồi

    @ManyToOne
    @JoinColumn(name = "user_id")
    private User user;
}

2. Logic Xoay Vòng tại AuthService

@Transactional
public TokenResponse refreshToken(String tokenStr) {
    RefreshToken rt = refreshTokenRepo.findByToken(tokenStr)
        .orElseThrow(() -> new RuntimeException("Token không tồn tại"));

    // 1. Kiểm tra hết hạn hoặc đã bị revoke
    if (rt.getExpiryDate().isBefore(Instant.now()) || rt.isRevoked()) {
        throw new TokenException("Token không hợp lệ hoặc đã dùng!");
    }

    // 2. Token Rotation: Hủy token cũ
    rt.setRevoked(true);
    refreshTokenRepo.save(rt);

    // 3. Cấp cặp Token mới
    String newAccess = jwtService.generateToken(rt.getUser());
    RefreshToken newRt = createRefreshToken(rt.getUser());

    return new TokenResponse(newAccess, newRt.getToken());
}

LESSON 3: PHÂN QUYỀN TRONG MICROSERVICES

Kiến Trúc Phân Quyền Đa Tầng (Gateway ⟷ Service Con)

API GATEWAY

Authentication & Blacklist
  • Xác thực chữ ký JWT: Giải mã token với Secret Key.
  • Redis Blacklist: Kiểm tra token có bị đăng xuất chưa.
  • Header Enrichment: Gắn X-User-Roles, X-User-Id chuyển tiếp xuống dưới.

RESOURCE SERVICES (Order / Product)

Authorization (RBAC / PBAC)
  • Spring Security Context: Nạp Authorities (ROLE_USER, ROLE_ADMIN).
  • Controller Protection: Bảo vệ API bằng @PreAuthorize.
  • Business Rules: Kiểm tra sở hữu tài nguyên (Resource Owner).

KẾT QUẢ TRẢ VỀ

Decision & Response
  • 200 OK: Đúng quyền Role ➔ Thực thi logic nghiệp vụ.
  • 403 Forbidden: Sai Role ➔ Chặn ngay tại tầng Controller.
LESSON 3: CODE TRIỂN KHAI

Cấu Hình Spring Security & Phân Quyền @PreAuthorize

1. Bật Method Security tại Service con

@Configuration
@EnableWebSecurity
@EnableMethodSecurity(prePostEnabled = true)
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(AbstractHttpConfigurer::disable)
            .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/public/**").permitAll()
                .anyRequest().authenticated()
            )
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }
}

2. Phân Quyền Chi Tiết ở Controller

@RestController
@RequestMapping("/api/orders")
public class OrderController {

    // 1. Cả USER và ADMIN đều có quyền xem
    @GetMapping
    @PreAuthorize("hasAnyRole('USER', 'ADMIN')")
    public List<Order> getOrders() { ... }

    // 2. CHỈ duy nhất ADMIN mới có quyền xóa
    @DeleteMapping("/{id}")
    @PreAuthorize("hasRole('ADMIN')")
    public ResponseEntity<?> deleteOrder(@PathVariable Long id) {
        orderService.delete(id);
        return ResponseEntity.ok("Xoá thành công đơn: " + id);
    }
}
LESSON 4: THU HỒI TOKEN & ĐĂNG XUẤT

Tại sao Đăng Xuất Stateless JWT bắt buộc cần Redis Blacklist?

Sai lầm: Chỉ xóa Token ở Frontend (LocalStorage)

Nhiều lập trình viên chỉ viết: localStorage.removeItem("token") khi bấm Đăng xuất.

Lỗ hổng bảo mật: Chuỗi JWT vẫn hoàn toàn hợp lệ về mặt chữ ký số! Nếu kẻ tấn công đã sao chép được token này trước đó, chúng vẫn có thể gửi request truy cập dữ liệu bình thường.

Giải pháp: Redis Blacklist với TTL Động

Công thức tính thời gian lưu Blacklist:
TTL = Thời điểm hết hạn (exp) − Thời điểm hiện tại (now)
  • Khi gọi /auth/logout: Lưu Access Token vào Redis với Key blacklist:<token> và gán EXPIRE = TTL.
  • Tối ưu bộ nhớ 100%: Khi Access Token tự nhiên hết hạn, Redis tự động giải phóng RAM, bảng Blacklist không bao giờ bị tràn bộ nhớ!
LESSON 4: CODE TRIỂN KHAI

Tích Hợp Redis Blacklist Trong Spring Boot

1. LogoutService (Lưu Redis với TTL)

@Service
public class LogoutService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    public void logout(String accessToken, String refreshToken) {
        // 1. Tính thời gian sống còn lại của JWT (ms)
        long remainingTtl = jwtService.getRemainingTime(accessToken);

        if (remainingTtl > 0) {
            // 2. Lưu vào Redis Blacklist kèm TTL tự hủy
            redisTemplate.opsForValue().set(
                "blacklist:" + accessToken,
                "REVOKED",
                remainingTtl,
                TimeUnit.MILLISECONDS
            );
        }
        // 3. Đánh dấu hủy Refresh Token trong DB
        refreshTokenRepo.revokeByToken(refreshToken);
    }
}

2. Chặn Request tại JwtAuthFilter

// Trong JwtAuthenticationFilter.doFilterInternal()
String token = extractTokenFromHeader(request);

if (token != null) {
    // Kiểm tra nhanh O(1) trong Redis Cache
    Boolean isBlacklisted = redisTemplate.hasKey("blacklist:" + token);

    if (Boolean.TRUE.equals(isBlacklisted)) {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write(
            "{\"error\": \"Token đã bị thu hồi do Đăng xuất!\"}"
        );
        return; // Chặn đứng request
    }
}

Bức Tranh Toàn Cảnh Bảo Mật Microservices Chuẩn Doanh Nghiệp

1. Dual-Token Architecture

Access Token ngắn hạn (Stateless) kết hợp Refresh Token Stateful có xoay vòng (Rotation) triệt tiêu hoàn toàn Replay Attack.

2. Multi-tier Authorization

Gateway đóng vai trò Authentication & Enrich Claims, Service con đảm nhiệm Authorization chi tiết bằng @PreAuthorize.

3. Redis Blacklist with TTL

Giải quyết bài toán Đăng xuất tức thì cho Stateless Token với mức tiêu thụ RAM tối ưu và tốc độ truy vấn O(1).
